<KeyIdea>
A Kotlin class declares its data **in the constructor**, so an object that exists is already
a valid object.
</KeyIdea>

## The shortest useful class

```kotlin title="User.kt" numbered runnable
class User(val name: String, var age: Int)

fun main() {
    val u = User("Asha", 30)
    println("${u.name} is ${u.age}")
    u.age = 31          // var, so this is allowed
    // u.name = "Ravi"  // val, so this is not
}
```

That one line declares a class, two properties, and a constructor that fills them.

<Detail summary="What Java needs for the same thing">
A field, a constructor parameter, an assignment and a getter — per property. Roughly fifteen
lines for what Kotlin says in one. The generated bytecode is the same.
</Detail>

## Where the parameters go

Kotlin has two constructors and beginners confuse them constantly.

<Tabs>
  <Tab label="Primary">

Sits in the class header. This is the one you want almost always.

```kotlin title="Primary.kt" numbered
class Order(
    val id: String,
    val items: List<String>,
    val discount: Int = 0,      // defaults work here too
)
```

  </Tab>
  <Tab label="Secondary">

Written inside the body with `constructor`. It must delegate to the primary using `: this(...)`.

```kotlin title="Secondary.kt" numbered
class Order(val id: String, val items: List<String>) {

    // convenience: build one from a single item
    constructor(id: String, item: String) : this(id, listOf(item))
}
```

  </Tab>
</Tabs>

<Tip bare>
Before writing a secondary constructor, try a default argument. It usually removes the need
for one entirely.
</Tip>

## `init`: the rules that must hold

A constructor parameter fills a property. An `init` block is where you say what must be
**true** about it.

```kotlin title="Init.kt" numbered runnable
class Order(val id: String, val quantity: Int) {

    init {
        require(id.isNotBlank()) { "id must not be blank" }
        require(quantity > 0) { "quantity must be positive" }
    }
}

fun main() {
    println(Order("A1", 2).id)
    println(runCatching { Order("", 2) }.exceptionOrNull()?.message)
}
```

Because this runs during construction, an `Order` that exists has passed the checks. There is
no half-built object to defend against later.

<Quiz

  options={[

  ]}

  explanation="They run strictly top to bottom, interleaved. That is why an init block cannot read a property declared below it — at that moment it has not been assigned yet."

## What an object looks like in memory

```kotlin title="Sharing.kt" numbered runnable
class Cart(val owner: String)

fun main() {
    val a = Cart("Asha")
    val b = a               // no copy — the same object
    println(a === b)        // true
}
```

## Common mistakes

<Pitfall title="Two that show up in every first project">
**Declaring properties in the body when they came from the constructor.** Writing
`class User(name: String) { val name = name }` works, but the parameter without `val` is not a
property — it only exists during construction. Put `val` in the header and delete the line.

**Doing real work in `init`.** Network calls, file reads or heavy loops there run before the
object is usable, on whatever thread constructed it. Keep `init` to validation and cheap
setup.
</Pitfall>

## Practice

1. Write `class Book(val title: String, val pages: Int)` and add an `init` that rejects a
   blank title and a non-positive page count.
2. Add a secondary constructor taking only a title, defaulting pages to 100. Then delete it
   and achieve the same with a default argument.
3. Put a `println` in an `init` block and in a property initialiser above it. Run it and
   confirm the order.
4. Create two variables pointing at one object, change a `var` through one, and read it
   through the other. Explain the result using the memory diagram above.

## Recap

| Piece | What it is for |
| --- | --- |
| `class Name(val x: T)` | Declare class, property and constructor at once |
| `val` / `var` in the header | Makes the parameter a property; without it, it is not |
| Default arguments | Usually replaces a secondary constructor |
| `constructor(...) : this(...)` | A secondary constructor, delegating to the primary |
| `init { }` | Validation; runs top to bottom with property initialisers |
| `require(...)` | Rejects bad arguments with a clear message |
