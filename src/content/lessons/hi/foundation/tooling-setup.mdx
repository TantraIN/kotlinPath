## यह क्यों जरूरी है

Setup वही जगह है जहाँ ज्यादातर लोग चुपचाप हार मान लेते हैं। मुश्किल इसलिए नहीं कि काम बड़ा है,
बल्कि इसलिए कि एक साथ पाँच अलग tools install हो जाते हैं और कोई यह नहीं बताता कि कौन सा क्या
है। फिर कुछ fail होता है और पता ही नहीं चलता कि गलती Studio की है, SDK की, Gradle की, JDK की,
या emulator की।

तो install तो करेंगे, पर हर चीज का नाम साथ-साथ रखते चलेंगे।

आपका project सिर्फ इतना लिखता है कि *कौन सी* SDK directory इस्तेमाल करनी है — और वह file
जान-बूझकर commit नहीं होती:

```properties title="local.properties" no-glossary
# Android Studio बनाता है। हर machine पर अलग — इसे कभी commit मत कीजिए।
sdk.dir=/Users/you/Library/Android/sdk
```

<Warning>
`local.properties` `.gitignore` में इसीलिए है: यह path हर machine पर अलग होता है। Commit कर
दिया तो teammate की build "SDK location not found" के साथ टूटेगी। इस file से दोबारा Git वाले
पाठ में मुलाकात होगी।
</Warning>

## पहले दिन के काम के commands

```bash title="Terminal" no-glossary
# कौन से devices दिख रहे हैं? Emulator और असली phone दोनों यहीं आते हैं।
adb devices -l

# बनी हुई APK install कीजिए
adb install app/build/outputs/apk/debug/app-debug.apk

# सिर्फ अपनी app के logs देखिए, system का शोर हटाकर
adb logcat --pid=$(adb shell pidof -s com.example.myapp)

# Build के लिए Android Studio खुला होना जरूरी नहीं
./gradlew assembleDebug

# जब कुछ बिना वजह पुराना चिपका रह जाए
./gradlew clean
```

<Tip bare>
`./gradlew` आपके project के अंदर committed एक script है। वह ठीक वही Gradle version download
करती है जो इस project को चाहिए, इसलिए build आपकी machine पर और CI server पर बिलकुल एक जैसी
चलती है। Android के लिए Gradle कभी globally install मत कीजिए।
</Tip>

## आम गलतियाँ

<Pitfall title="तीन गलतियाँ जो कई घंटे खा जाती हैं">
**धीमा emulator।** लगभग हमेशा architecture mismatch, या hardware acceleration बंद होना।
देखिए कि system image आपके CPU से match करता है, और virtualisation चालू है — Windows पर
Hyper-V या WHPX, Linux पर KVM।

**दो JDK आपस में लड़ते हुए।** Studio अपना JDK लेकर आता है; आपका terminal कोई और इस्तेमाल कर रहा
हो सकता है। जब build IDE में और terminal में अलग behave करे, वजह यही होती है। दोनों को एक ही पर
point कीजिए: Settings → Build Tools → Gradle → Gradle JDK।

**`local.properties` commit कर देना।** Machine-specific paths version control में बाकी सबकी
build तोड़ते हैं। अगर पहले से committed है तो उसे tracking से हटाइए और `.gitignore` में डालिए।
</Pitfall>

## अभ्यास

1. बिना कुछ connect किए `adb devices -l` चलाइए, फिर emulator चालू करके। क्या बदला?
2. अपनी SDK directory ढूँढ़िए और `platforms/` list कीजिए। कौन से API levels install हैं?
3. Android Studio बंद करके terminal से `./gradlew assembleDebug` चलाइए। APK कहाँ बनी?
4. Build के बीच में जान-बूझकर emulator बंद कर दीजिए। Error पढ़िए। चार टुकड़ों में से किसने वह
   message दिया?

## सारांश

| Tool | जो command सबसे ज्यादा लिखेंगे |
| --- | --- |
| Gradle wrapper | `./gradlew assembleDebug` |
| adb | `adb devices -l`, `adb install`, `adb logcat` |
| SDK Manager | Studio के अंदर: Settings → SDK |
| Device Manager | Studio के अंदर: AVD बनाइए और boot कीजिए |

आगे बढ़ने से पहले checklist: Studio खुलता है, `adb devices` में कोई device या emulator दिखता है,
और terminal से `./gradlew assembleDebug` सफल होता है। तीनों सच हैं तो आपकी machine बाकी course
के लिए तैयार है।
