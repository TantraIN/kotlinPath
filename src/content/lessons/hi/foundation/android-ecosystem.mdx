## यह क्यों जरूरी है

Android पहले ही दिन आपसे ऐसे फैसले करवाता है जो तभी समझ आते हैं जब नीचे का ढाँचा पता हो: कौन
सा `minSdk` support करना है, आपकी app दूसरी app की files क्यों नहीं पढ़ सकती, और `targetSdk`
बदलने से वह behaviour क्यों बदल जाता है जो आपने लिखा ही नहीं।

इनमें से कोई चीज मनमानी नहीं है। हर एक architecture से निकलती है। यहाँ पंद्रह मिनट लगाने से आप
वे settings copy-paste करने से बच जाएँगे जिनका मतलब पता ही नहीं।

## ART, JVM नहीं है

पिछला पाठ एक सवाल पर खत्म हुआ था: Android साधारण JVM क्यों नहीं भेज सकता?

क्योंकि phone server नहीं है। उसमें छोटी battery है, कम RAM है, और एक user spinner देख रहा
होता है। Android ने JVM की जगह **Android Runtime** रखा, जो अलग trade-offs करता है।

## Sandbox

Android का सबसे ज्यादा असर डालने वाला design फैसला यही है: **हर app को अपना अलग Linux user
ID मिलता है।**

यह कोई उपमा नहीं है — सच में एक user, जैसे server पर `root` और `www-data` users होते हैं।
आपकी app की files उस user की हैं, और बाकी काम Linux की file permissions कर देती हैं।

```bash title="Terminal" no-glossary
# दो apps, दो बिलकुल अलग पहचान
adb shell ps -A | grep -E "com.example|com.android.chrome"

u0_a142  ...  com.example.myapp
u0_a201  ...  com.android.chrome
```

बाकी सब इसी से निकलता है:

- दूसरी app आपका database नहीं पढ़ सकती, क्योंकि वह file उसके user के लिए readable ही नहीं है।
- Permission का मतलब है system आपके user ID को sandbox के बाहर की किसी चीज तक पहुँच दे रहा है
  — camera, network, user के contacts।
- हर app अपने अलग process और अपने runtime instance में चलती है, इसलिए एक app का crash दूसरी
  को नहीं ले डूबता।

<Note>
इसीलिए "file SD card पर लिख दो और दूसरी app से पढ़ लो" वाला तरीका सालों पहले बंद हो गया, और
इसीलिए Android पर हर storage सवाल घूम-फिरकर यही बन जाता है कि file किस sandbox में पड़ी है।
Scoped storage Phase 8 में विस्तार से आएगा।
</Note>

## API level: असली number

लोग कहते हैं "Android 15"। Platform कहता है **API level 35**। एक ही release के दो नाम हैं, और
build API level वाला नाम इस्तेमाल करती है।

| Setting | मतलब | क्या रखें |
| --- | --- | --- |
| `compileSdk` | किस API के against code compile होगा | हमेशा latest stable |
| `minSdk` | सबसे पुराना device जो app install कर सके | जितना नीचे आपके users को चाहिए |
| `targetSdk` | किस behaviour के against app test की गई है | Latest, और सोच-समझकर बढ़ाएँ |

`targetSdk` सबसे सूक्ष्म है। System इसे पढ़कर तय करता है कि आपके साथ कितनी सख्ती करनी है। इसे
बढ़ाइए और behaviour बदल जाते हैं — background limits कस जाती हैं, permissions सख्त हो जाती हैं
— बिना आपके एक line बदले। Google Play भी इसे recent रखना जरूरी करता है, तो यह optional नहीं है।

<Pitfall title="दो मान्यताएँ जो असली apps तोड़ती हैं">
**Compile हो गया मतलब class है — यह मान लेना।** `compileSdk 35` आपको level 33 में जुड़ा API
call करने देता है। `minSdk 24` वाले device पर वह class है ही नहीं, और app `NoSuchMethodError`
के साथ crash हो जाती है। Guard लगाइए:
`if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU)`।

**Warning छुपाने के लिए `targetSdk` बढ़ा देना।** यह एक घोषणा है कि आपने उस version के behaviour
changes के against test कर लिया है। बढ़ाइए, फिर app सच में चलाइए — release से एक रात पहले मत
बढ़ाइए।
</Pitfall>

## अभ्यास

1. इन सबकी layer बताइए: `SQLite`, `Activity`, camera driver, `PackageManager`, DEX execution.
2. आपकी app सिर्फ पुराने phones पर `NoSuchMethodError` देती है। तीन SDK settings में से कौन सी
   गलत है, और fix क्या है?
3. Sandbox के आधार पर समझाइए कि एक to-do app, banking app का saved session क्यों नहीं पढ़ सकती
   — बिना "security" शब्द इस्तेमाल किए।
4. आपका APK 40 MB का है। दो वजहें बताइए कि AAB से असली download छोटा क्यों हो जाएगा।

## सारांश

| शब्द | एक line |
| --- | --- |
| Linux kernel | सबसे नीचे की layer; user-ID sandbox का स्रोत |
| HAL | अलग-अलग manufacturers के hardware तक स्थिर interface |
| ART | Android का runtime — DEX चलाता है, पहले ही compile करता है |
| DEX | Android का bytecode format, R8 बनाता है |
| Sandbox | हर app का एक Linux user; permission उसके बाहर की अनुमति है |
| API level | वह number जिसे build target करती है, जैसे Android 15 के लिए 35 |
| AAB | जो आप upload करते हैं; Play इससे per-device APK बनाता है |

<Interview title="यह देखने के लिए पूछा जाता है कि platform समझ आया या सिर्फ SDK">
"`minSdk`, `targetSdk` और `compileSdk` में क्या फर्क है?"

जो जवाब जमता है: `compileSdk` compile time है, `minSdk` install time है, `targetSdk` run time
है। फिर हर एक के गलत होने का नतीजा बताइए — code compile ही नहीं होगा, users install नहीं कर
पाएँगे, और वह behaviour बदल जाएगा जो आपने कभी test ही नहीं किया।
</Interview>
