<KeyIdea>
हर coroutine किसी **scope** का होता है। Scope cancel कीजिए और उसके अंदर का हर coroutine cancel हो
जाता है — screen जाते ही काम इसी तरह रुकता है।
</KeyIdea>

## Scope जगह नहीं, उम्र है

```kotlin title="Scope.kt" numbered runnable
import kotlinx.coroutines.*

fun main() = runBlocking {
    val scope = CoroutineScope(Job())

    scope.launch { repeat(5) { println("tick $it"); delay(100) } }
    delay(250)

    scope.cancel()              // अंदर का सब रुक जाता है
    delay(200)
    println("done")
}
```

Coroutine से विनम्रता से ख़त्म होने को नहीं कहा जाता। पूरा scope cancel होता है, और उसके सारे बच्चे उसके
साथ।

## Context कई हिस्सों का set है

`CoroutineContext` एक map जैसा set है जिसे आप `+` से जोड़ सकते हैं।

```kotlin title="Context.kt" numbered
val scope = CoroutineScope(
    SupervisorJob() + Dispatchers.Main + CoroutineName("profile")
)
```

| हिस्सा | किस सवाल का जवाब |
| --- | --- |
| `Job` | यह cancel कैसे होगा, और इसका parent कौन है? |
| `CoroutineDispatcher` | यह किस thread पर चलेगा? |
| `CoroutineName` | Debugger में क्या दिखेगा? |
| `CoroutineExceptionHandler` | बिना पकड़ी ग़लतियाँ कहाँ जाएँगी? |

## Android पर मुफ़्त मिलने वाले scopes

<Tabs>
  <Tab label="viewModelScope">

ViewModel clear होते ही cancel। Screen के logic के लिए यही default चुनाव है।

```kotlin title="ViewModel.kt" numbered
class ProfileViewModel : ViewModel() {
    fun load() = viewModelScope.launch {
        val user = repository.user()      // user चला जाए तो cancel
    }
}
```

  </Tab>
  <Tab label="lifecycleScope">

Activity या Fragment के lifecycle से जुड़ा हुआ। उस काम के लिए जो सच में view का है।

```kotlin title="Lifecycle.kt" numbered
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.state.collect { render(it) }
    }
}
```

  </Tab>
  <Tab label="अपना">

ऐसे component के लिए जिसकी अपनी उम्र हो — repository, cache।

```kotlin title="Own.kt" numbered
class SyncEngine {
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
    fun stop() = scope.cancel()          // यह आपको ख़ुद बुलाना पड़ेगा
}
```

  </Tab>
</Tabs>

<Detail summary="GlobalScope, और वह लगभग मना क्यों है">
`GlobalScope` की कोई उम्र ही नहीं — उसे कभी कुछ cancel नहीं करता। वहाँ शुरू किया काम screen जाने के
बाद भी चलता रहता है, और जो पकड़ा था उसे पकड़े रहता है। यह coroutine वाला leaked thread है, और
`viewModelScope` के होने की वजह भी।
</Detail>

## आम ग़लतियाँ

<Pitfall title="दो जो leak करती हैं">
**Scope बनाकर कभी cancel न करना।** जो `CoroutineScope` आपने हाथ से बनाया, उसे cancel करना भी आपका काम
है। अगर रखने वाले object का lifecycle है, तो उसके ख़त्म होने पर cancel कीजिए।

**`GlobalScope` इसलिए इस्तेमाल करना क्योंकि वह compile हो जाता है।** वह हमेशा compile होता है। और
screen, ViewModel और cancel करने की हर कोशिश — तीनों से ज़्यादा जीता है।
</Pitfall>

## अभ्यास

1. सादे `Job` से scope बनाइए, तीन children launch कीजिए, एक में exception फेंकिए, और बाक़ी दो को
   देखिए। फिर `SupervisorJob` डालकर दोबारा चलाइए।
2. Scope में `CoroutineName` जोड़िए और अंदर `coroutineContext[CoroutineName]` print कीजिए।
3. `viewModelScope` में काम शुरू कीजिए, फिर screen छोड़िए और `finally` block में log करके साबित कीजिए
   कि cancellation हुई।
4. एक line में समझाइए कि Fragment में `GlobalScope.launch` leak क्यों है।
