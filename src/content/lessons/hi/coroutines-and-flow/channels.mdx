<KeyIdea>
`Channel` हर value **ठीक एक** receiver को देता है, और एक ही बार देता है। `Flow` हर collector को भेजता
है। बस यही एक फर्क तय करता है कि आपको कौन सा चाहिए।
</KeyIdea>

## ऐसी कतार जिसके दोनों सिरों पर coroutine है

```kotlin title="Channel.kt" numbered runnable
import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*

fun main() = runBlocking {
    val channel = Channel<Int>()

    launch {
        repeat(3) { channel.send(it); delay(50) }
        channel.close()
    }

    for (value in channel) println("received $value")
    println("channel closed")
}
```

`send` तब तक suspend रहता है जब तक कोई receiver value न ले ले। `close` loop खत्म करता है। Values देखी
नहीं जातीं, खप जाती हैं।

## मजा capacity में है

| Capacity | `send` का व्यवहार |
| --- | --- |
| `RENDEZVOUS` (default) | Receiver तैयार होने तक suspend |
| `BUFFERED` | सिर्फ buffer भरने पर suspend |
| `CONFLATED` | कभी suspend नहीं; रखी हुई value की जगह ले लेता है |
| `UNLIMITED` | कभी suspend नहीं; बिना सीमा बढ़ता है |

<Pitfall bare>
`UNLIMITED` back-pressure पूरी तरह हटा देता है। अगर बनाने वाला खपाने वाले से तेज है, तो कतार तब तक
बढ़ती है जब तक app की memory खत्म न हो जाए।
</Pitfall>

## आपको शायद Flow ही चाहिए

```kotlin title="Prefer.kt" numbered
// Channel जिसे आपको बनाना, रखना और बंद करना पड़ता है
private val events = Channel<Event>()

// Flow जो अपनी उम्र खुद सँभालता है
val events: SharedFlow<Event> = _events.asSharedFlow()
```

| चाहिए | क्या इस्तेमाल करें |
| --- | --- |
| Screen state | `StateFlow` |
| एक बार वाले UI events, कई देखने वाले | `SharedFlow` |
| N workers में काम बाँटना | `Channel` |
| Back-pressure के साथ एक producer और एक consumer | `Channel` |
| जो भी चीज `close` करना याद रखना पड़े | `Flow` |

<Detail summary="channelFlow — वह पुल जो आप सच में इस्तेमाल करेंगे">
असली आम जरूरत किसी callback API को लपेटने की होती है। `callbackFlow` आपको Flow के अंदर एक Channel देता
है: callback से आप `trySend` करते हैं, और collector के जाने पर `awaitClose` listener हटा देता है।
Channel का तरीका मिलता है, Flow की उम्र सँभालने के साथ।

```kotlin
fun locations(): Flow<Location> = callbackFlow {
    val listener = LocationListener { trySend(it) }
    manager.register(listener)
    awaitClose { manager.unregister(listener) }
}
```
</Detail>

## आम गलतियाँ

<Pitfall title="दो जो आसानी से लग जाती हैं">
**`close` करना भूल जाना।** बिना बंद किए Channel पर `for` loop हमेशा के लिए इंतजार करता रहता है, और
coroutine कभी खत्म नहीं होता। Flow में ऐसा कोई जाल है ही नहीं।

**State के लिए Channel इस्तेमाल करना।** हर value सिर्फ एक receiver को दिखती है, इसलिए दूसरे देखने वाले
को कुछ नहीं मिलता और phone घुमाने पर value पूरी तरह खो जाती है।
</Pitfall>

## अभ्यास

1. दो producers से एक Channel में भेजिए और एक consumer से receive कीजिए। क्रम ध्यान से देखिए।
2. `capacity = CONFLATED` रखिए, receive से तेज भेजिए, और देखिए कौन सी values बचती हैं।
3. Listener वाले किसी API को `callbackFlow` से लपेटिए और confirm कीजिए कि cancel पर `awaitClose`
   चलता है।
4. जहाँ `SharedFlow` चाहिए था वहाँ Channel इस्तेमाल कीजिए, एक और collector जोड़िए, और देखिए क्या टूटता
   है।

## सारांश

| बात | विवरण |
| --- | --- |
| पहुँचाना | एक value, एक receiver — खप जाती है, देखी नहीं जाती |
| `send` / `receive` | दोनों suspend होते हैं; यही back-pressure है |
| `close` | जरूरी, वरना receivers हमेशा इंतजार करते रहते हैं |
| Capacity | `RENDEZVOUS`, `BUFFERED`, `CONFLATED`, `UNLIMITED` |
| `callbackFlow` | Channel का वही इस्तेमाल जो सच में काम आएगा |
| Default चुनाव | Flow, जब तक आप काम बाँट न रहे हों |
