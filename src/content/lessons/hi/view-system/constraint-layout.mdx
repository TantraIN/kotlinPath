<KeyIdea>
हर view को कम से कम एक **आड़ी** और एक **खड़ी** constraint चाहिए, वरना वह ऊपर-बाएँ कोने में जा
बैठती है। Chains, guidelines और barriers इसीलिए हैं ताकि views के आपसी रिश्ते के लिए कभी nesting
का एक और स्तर न जोड़ना पड़े।
</KeyIdea>

## यह क्यों जरूरी है

पिछला पाठ nesting की कीमत पर खत्म हुआ था: हर स्तर एक और measure pass है, और weight वाला स्तर दो।
चार nested `LinearLayout` से बनी screen यह कीमत हर frame पर चुकाती है।

`ConstraintLayout` वही बात एक ही स्तर में कह देता है। बदले में जगहें ऐसे रिश्ते बन जाती हैं जो आप
बताते हैं, न कि ऐसा ढाँचा जो आप खड़ा करते हैं।

## Constraint दो किनारों की जोड़ी है

```xml title="res/layout/card.xml" numbered
<androidx.constraintlayout.widget.ConstraintLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content">

    <ImageView
        android:id="@+id/avatar"
        android:layout_width="48dp"
        android:layout_height="48dp"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent" />

    <TextView
        android:id="@+id/title"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        app:layout_constraintStart_toEndOf="@id/avatar"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="@id/avatar" />
</androidx.constraintlayout.widget.ConstraintLayout>
```

हर attribute को *मेरा किनारा, तुम्हारे किनारे से* की तरह पढ़िए: `Start_toEndOf` का मतलब है "मेरा
start किनारा तुम्हारे end किनारे से जुड़ता है"। दोनों आमने-सामने के किनारे बाँध दीजिए और view
उनके बीच में आ जाती है।

## Chain एक row को बाँटती है

Chain दो या ज्यादा views हैं जो दोनों दिशाओं में एक-दूसरे से बँधी हों। Chain की पहली view —
**head** — style तय करती है।

| `layout_constraintHorizontal_chainStyle` | नतीजा |
| --- | --- |
| `spread` | हर view के चारों तरफ जगह बराबर बँटती है (default) |
| `spread_inside` | बाहरी views किनारों से चिपकती हैं, जगह बाकी के बीच बँटती है |
| `packed` | Views पास-पास आ जाती हैं, और पूरा गुच्छा `bias` से जमता है |

Chain वालों को `0dp` और `layout_constraintHorizontal_weight` दे दीजिए, और ठीक वही मिलेगा जो
`LinearLayout` में `layout_weight` देता था — बिना उस अतिरिक्त measure pass के।

```xml title="Barrier.xml" numbered
<androidx.constraintlayout.widget.Barrier
    android:id="@+id/labelEnd"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    app:barrierDirection="end"
    app:constraint_referenced_ids="nameLabel,emailLabel,phoneLabel" />
```

फिर हर value वाला field अपना start `@id/labelEnd` से बाँध देता है, और column सीधा रहता है चाहे
कोई भी label सबसे लंबा हो — translator के किसी label को दुगना कर देने के बाद भी।

<Detail summary="`bias`, और दोनों तरफ बँधी होने पर वह करता क्या है">
View के दोनों आमने-सामने किनारे बाँध दीजिए तो वह बीच में आ जाती है।
`layout_constraintHorizontal_bias` उसे उसी फैलाव पर खिसकाता है: `0.0` शुरू में, `1.0` अंत में,
`0.5` बीच में — और यही default है।

```xml title="Bias.xml"
app:layout_constraintStart_toStartOf="parent"
app:layout_constraintEnd_toEndOf="parent"
app:layout_constraintHorizontal_bias="0.25"
```

बिना guideline के किसी चीज को चौथाई दूरी पर रखने का यही तरीका है — और तय margin के उलट, यह हर
screen की चौड़ाई पर टिका रहता है।
</Detail>

## आम गलतियाँ

<Pitfall title="चार, जिनसे view कोने में जा बैठती है">
**एक दिशा में constraint छूट जाना।** आड़ी बाँध दी पर खड़ी नहीं, तो view चुपचाप ऊपर बैठ जाती है।
Editor बताता है; build नहीं।

**किसी child पर `match_parent`।** यहाँ यह support ही नहीं है। दोनों तरफ constraints के साथ `0dp`
इस्तेमाल कीजिए।

**`ConstraintLayout` के अंदर `ConstraintLayout`।** चल तो जाता है, और जिस वजह से आपने उसे चुना था
वही फेंक देता है। पहले chain, guideline या barrier की तरफ जाइए।

**जहाँ barrier चाहिए वहाँ guideline।** तय रेखा अंग्रेजी में सही दिखती है और translate किया हुआ
label लंबा होते ही टूट जाती है।
</Pitfall>

## अभ्यास

1. सिर्फ आड़ी constraint वाली एक view रखिए। चलाइए, फिर खड़ी वाली भी जोड़िए।
2. तीन views की एक row chain बनाइए, और head को `spread`, `spread_inside` और `packed` से घुमाइए।
3. 30% पर guideline रखकर दो-column वाला form बनाइए। फिर guideline की जगह barrier रखिए और एक
   label की लंबाई दुगनी कर दीजिए।
4. Nested `LinearLayout` से बनी कोई screen लेकर उसे सपाट कीजिए। Layout Inspector में गहराई
   मिलाइए।

## सारांश

| चीज | एक line |
| --- | --- |
| Constraint | *मेरा किनारा, तुम्हारे किनारे से*; हर दिशा में कम से कम एक |
| `0dp` | Match constraints — `match_parent` की जगह यही |
| `match_parent` | Child पर support ही नहीं |
| Chain | आपस में बँधी views; head style तय करती है |
| `spread` / `spread_inside` / `packed` | Chain जगह कैसे बाँटती है |
| Guideline | Percent या dp पर तय, न दिखने वाली रेखा |
| Barrier | सबसे बड़ी बताई गई view के पीछे चलने वाली रेखा |
| `bias` | बँधे हुए फैलाव पर view कहाँ बैठेगी |

से सेट की गई guideline label लंबा होते ही टूट जाती है, वही हिस्सा है जो tutorial नहीं, असली screen
जैसा लगता है।
