<KeyIdea>
Extension class में जुड़ता नहीं है। वह एक सादा function है जिसका पहला parameter receiver है, बस उसे
dot से बुलाने लायक बना दिया गया है।
</KeyIdea>

## समस्या

आपको `"asha@mail.com".isEmail()` चाहिए। `String` आपका है नहीं, और वैसे भी वह `final` है।

```kotlin title="Extensions.kt" numbered runnable
fun String.isEmail(): Boolean =
    contains("@") && substringAfter("@").contains(".")

val String.initials: String
    get() = split(" ").mapNotNull { it.firstOrNull() }.joinToString(".")

fun main() {
    println("asha@mail.com".isEmail())
    println("nope".isEmail())
    println("Asha Rao Patel".initials)
}
```

Body के अंदर `this` ही receiver है — और Kotlin के हर `this` की तरह, उसे छोड़ा जा सकता है।

<Detail summary="Compiler असल में बनाता क्या है">
`fun String.isEmail()` एक static method बनता है जिसका पहला argument `String` है। `"x".isEmail()`
लिखना `StringExtKt.isEmail("x")` बन जाता है। `String` में कुछ जुड़ा नहीं; पूरी खूबी बस dot वाला
syntax है।
</Detail>

## वह नतीजा जिसे लोग गलत समझते हैं

क्योंकि यह static function है, यह **लिखे हुए type** से तय होता है, चलते वक्त वाले type से नहीं।

```kotlin title="Dispatch.kt" numbered runnable
open class Animal
class Dog : Animal()

fun Animal.speak() = "generic noise"
fun Dog.speak() = "woof"

fun main() {
    val pet: Animal = Dog()
    println(pet.speak())        // "generic noise" — "woof" नहीं
}
```

<Pitfall bare>
एक ही signature वाले member function के सामने extension हमेशा हार जाता है। अगर library के किसी नए
version ने वह member जोड़ा, तो आपका extension चुपचाप बुलाया जाना बंद हो जाएगा।
</Pitfall>

## Extensions सच में कहाँ काम आते हैं

<Tabs>
  <Tab label="Nullable receiver">

Receiver null हो सकता है, इसलिए null check अंदर ही रहता है।

```kotlin title="Nullable.kt" numbered runnable
fun String?.orPlaceholder(): String =
    if (this.isNullOrBlank()) "—" else this

fun main() {
    val missing: String? = null
    println(missing.orPlaceholder())    // call site पर `?.` की जरूरत नहीं
}
```

  </Tab>
  <Tab label="Class के अंदर">

Class के अंदर लिखा हुआ, इसलिए सिर्फ वहीं मौजूद है जहाँ उसका मतलब है।

```kotlin title="Scoped.kt" numbered
class Formatter(private val symbol: String) {

    // सिर्फ Formatter के अंदर दिखता है
    fun Int.money(): String = "$symbol$this"

    fun render(amount: Int) = amount.money()
}
```

  </Tab>
  <Tab label="Generic">

हर element type पर चलता है, कहीं कोई subclass बनाए बिना।

```kotlin title="Generic.kt" numbered runnable
fun <T> List<T>.second(): T? = getOrNull(1)

fun main() = println(listOf("a", "b", "c").second())
```

  </Tab>
</Tabs>

## आम गलतियाँ

<Pitfall title="दो जो codebase पढ़ना मुश्किल कर देती हैं">
**अपने ही type को extend करना।** अगर आप member जोड़ सकते हैं, member जोड़िए। वह virtually dispatch
होता है, class में दिखता है, और override हो सकता है। Extensions उन types के लिए हैं जिन्हें आप बदल
नहीं सकते।

**साझे module में `Any` या `String` पर extensions।** वे project की हर `String` के autocomplete में आ
जाते हैं। ऐसे चौड़े receivers को `private` या `internal` रखिए, जब तक पूरी team उन्हें न चाहे।
</Pitfall>

## अभ्यास

1. `fun Int.isEven()` लिखिए और उसे `filter` में इस्तेमाल कीजिए। फिर वही चीज top-level
   `fun isEven(n: Int)` से लिखिए — कौन सा call site बेहतर पढ़ता है?
2. `fun List<Int>.average2()` जोड़िए, फिर अपने वाले का नाम `average()` रखकर देखिए कि standard library
   वाला ही जीतता है।
3. एक extension property लिखिए — `val LocalDate.isWeekend: Boolean`।
4. ऊपर वाला `Animal`/`Dog` नतीजा दोबारा बनाइए, फिर `speak()` को member बनाकर चलाइए। फर्क एक line में
   समझाइए।

## सारांश

| बात | विवरण |
| --- | --- |
| बनता क्या है | Static function, receiver पहला parameter |
| Dispatch | Static — लिखा हुआ type, चलते वक्त वाला नहीं |
| Member बनाम extension | Member हमेशा जीतता है |
| Nullable receiver | चलता है, और अक्सर वही मकसद है |
| कब इस्तेमाल करें | जो types आपके नहीं, या सीमित दायरे के helpers |
