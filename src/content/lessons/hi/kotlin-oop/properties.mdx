<KeyIdea>
Kotlin की हर property असल में **दो functions का जोड़ा** है। इसीलिए `user.fullName` मौक़े पर बन सकता
है और बुलाने वाले को पता भी नहीं चलता।
</KeyIdea>

## रखी हुई और बनी हुई

```kotlin title="Computed.kt" numbered runnable
class User(val first: String, val last: String) {

    // कोई जगह नहीं घेरी — हर बार पढ़ने पर बनता है
    val fullName: String
        get() = "$first $last"

    // रखी हुई, पर लिखते वक़्त जाँची जाती है
    var age: Int = 0
        set(value) {
            field = if (value < 0) 0 else value
        }
}

fun main() {
    val u = User("Asha", "Rao")
    println(u.fullName)
    u.age = -5
    println(u.age)      // 0
}
```

`field` ही **backing field** है — असली जगह। वह सिर्फ़ accessor के अंदर होता है, और तभी जब आप उसे
लिखें। `fullName` उसका नाम ही नहीं लेता, इसलिए उसके लिए कोई जगह बनती ही नहीं।

## Value को टालने के तीन तरीक़े

<Tabs>
  <Tab label="lateinit">

ऐसे `var` के लिए जिसे आप पहले इस्तेमाल से पहले भर देंगे, आम तौर पर framework callback से।

```kotlin title="Lateinit.kt" numbered
class ProfileScreen {
    private lateinit var binding: Binding      // onCreate में assign होगा

    fun onCreate() { binding = Binding() }
    fun render() = binding.show()              // onCreate न चला तो फेंकता है
}
```

सिर्फ़ `var` पर, सिर्फ़ non-null object types पर — `Int`, `Boolean` या `String?` पर कभी नहीं।

  </Tab>
  <Tab label="lazy">

ऐसे `val` के लिए जो महँगा है और शायद कभी चाहिए ही न हो।

```kotlin title="Lazy.kt" numbered runnable
class Repo {
    val database: String by lazy {
        println("building…")      // ज़्यादा से ज़्यादा एक बार
        "connection"
    }
}

fun main() {
    val repo = Repo()
    println("created")            // अभी कुछ नहीं बना
    println(repo.database)        // अब बना
    println(repo.database)        // cache से
}
```

Default से thread-safe; एक ही thread छूता हो तो `LazyThreadSafetyMode.NONE` दीजिए।

  </Tab>
  <Tab label="nullable">

ईमानदार चुनाव, जब value सच में ग़ायब हो सकती हो।

```kotlin title="Nullable.kt" numbered
class Session {
    var user: User? = null        // यहाँ ग़ायब होना एक असली स्थिति है
}
```

  </Tab>
</Tabs>

<Detail summary="lateinit सिर्फ़ कम typing वाला nullable क्यों नहीं है">
`lateinit` null का *check* हटाता है, null नहीं। जल्दी पढ़ने पर
`UninitializedPropertyAccessException` आता है — लंबे नाम वाला `NullPointerException`, और
compiler से कोई मदद नहीं। इसे तभी उठाइए जब framework assignment का क्रम guarantee करता हो।
</Detail>

## आम ग़लतियाँ

<Pitfall title="दो जो अभी नहीं, बाद में काटती हैं">
**महँगा computed property।** `val total get() = items.sumOf { it.price }` मुफ़्त लगता है और हर बार
पढ़ने पर दोबारा चलता है। Compose के `LazyColumn` में वह हर item पर, हर frame में चलेगा। या उसे store
कीजिए, या function बना दीजिए ताकि क़ीमत call site पर दिखे।

**Fragment की view binding पर `lateinit`।** View, Fragment से पहले मर जाती है, इसलिए
`onDestroyView` के बाद उसे छूने वाला कुछ भी फेंकता है। उसकी जगह nullable-backed pattern इस्तेमाल
कीजिए।
</Pitfall>

## अभ्यास

1. `User` में एक computed `initials` property जोड़िए जो `"A.R."` लौटाए। साबित कीजिए कि उसका
   backing field नहीं है — देखिए कि उसे initialiser चाहिए ही नहीं।
2. एक `var password: String` लिखिए जिसका setter आठ से छोटी चीज़ को मना कर दे और पुरानी value बचाए
   रखे।
3. एक महँगे object को `by lazy` में लपेटिए और पहले पढ़ने से पहले-बाद print करके साबित कीजिए कि वह
   कब बना।
4. एक `lateinit var` को nullable `var` में बदलिए और ग़ायब होने को `?:` से सँभालिए। रात दो बजे किस
   version को debug करना पसंद करेंगे?

## सारांश

| Tool | कब |
| --- | --- |
| `get() =` | Value दूसरी properties से निकल आती हो |
| `set(value) { field = ... }` | हर लिखाई जाँचनी या सुधारनी हो |
| `field` | Accessor के अंदर, असली जगह तक पहुँचने के लिए |
| `lateinit var` | Framework पहले इस्तेमाल से पहले भर देता हो |
| `by lazy { }` | महँगा, read-only, शायद कभी चाहिए ही न हो |
| `T?` | ग़ायब होना एक असली, अपेक्षित स्थिति हो |
