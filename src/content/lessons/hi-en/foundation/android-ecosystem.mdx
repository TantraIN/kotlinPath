## Ye kyun zaruri hai

Android pehle hi din aapse aise faisle karwata hai jo tabhi samajh aate hain jab neeche ka
dhaancha pata ho: kaun sa `minSdk` support karna hai, aapki app dusri app ki files kyun
nahi padh sakti, aur `targetSdk` badalne se wo behaviour kyun badal jata hai jo aapne likha
hi nahi.

In mein se koi cheez manmaani nahi hai. Har ek architecture se nikalti hai. Yahan pandrah
minute lagane se aap wo settings copy-paste karne se bach jaoge jinka matlab pata hi nahi.

## ART, JVM nahi hai

Pichhla lesson ek sawal par khatam hua tha: Android saada JVM kyun nahi bhej sakta?

Kyunki phone server nahi hai. Usmein chhoti battery hai, kam RAM hai, aur ek user spinner
dekh raha hota hai. Android ne JVM ki jagah **Android Runtime** rakha, jo alag trade-offs
karta hai.

## Sandbox

Android ka sabse zyada asar daalne wala design faisla yahi hai: **har app ko apna alag
Linux user ID milta hai.**

Ye koi upma nahi hai — sach mein ek user, jaise server par `root` aur `www-data` users hote
hain. Aapki app ki files us user ki hain, aur baaki kaam Linux ki file permissions kar deti
hain.

```bash title="Terminal" no-glossary
# Do apps, do bilkul alag pehchaan
adb shell ps -A | grep -E "com.example|com.android.chrome"

u0_a142  ...  com.example.myapp
u0_a201  ...  com.android.chrome
```

Baaki sab isi se nikalta hai:

- Dusri app aapka database nahi padh sakti, kyunki wo file uske user ke liye readable hi
  nahi hai.
- Permission ka matlab hai system aapke user ID ko sandbox ke bahar ki kisi cheez tak
  pahunch de raha hai — camera, network, user ke contacts.
- Har app apne alag process aur apne runtime instance mein chalti hai, isliye ek app ka
  crash dusri ko nahi le doobta.

<Note>
Isiliye "file SD card par likh do aur dusri app se padh lo" wala tarika saalon pehle band ho
gaya, aur isiliye Android par har storage sawal ghoom-phirkar yahi ban jata hai ki file kis
sandbox mein padi hai. Scoped storage Phase 8 mein detail se aayega.
</Note>

## API level: asli number

Log kehte hain "Android 15". Platform kehta hai **API level 35**. Ek hi release ke do naam
hain, aur build API level wala naam use karti hai.

| Setting | Matlab | Kya rakho |
| --- | --- | --- |
| `compileSdk` | Kis API ke against code compile hoga | Hamesha latest stable |
| `minSdk` | Sabse purana device jo app install kar sake | Jitna neeche aapke users ko chahiye |
| `targetSdk` | Kis behaviour ke against app test ki gayi hai | Latest, aur soch-samajh kar badhao |

`targetSdk` sabse sookshm hai. System ise padhkar tay karta hai ki aapke saath kitni sakhti
karni hai. Ise badhao aur behaviour badal jate hain — background limits kas jati hain,
permissions sakht ho jati hain — bina aapke ek line badle. Google Play bhi ise recent rakhna
zaruri karta hai, to ye optional nahi hai.

<Pitfall title="Do maanyataayein jo asli apps todti hain">
**Compile ho gaya matlab class hai — ye maan lena.** `compileSdk 35` aapko level 33 mein
juda API call karne deta hai. `minSdk 24` wale device par wo class hai hi nahi, aur app
`NoSuchMethodError` ke saath crash ho jati hai. Guard lagao:
`if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU)`.

**Warning chupane ke liye `targetSdk` badha dena.** Ye ek ghoshna hai ki aapne us version ke
behaviour changes ke against test kar liya hai. Badhao, phir app sach mein chalao — release
se ek raat pehle mat badhao.
</Pitfall>

## Practice

1. In sabki layer batao: `SQLite`, `Activity`, camera driver, `PackageManager`, DEX
   execution.
2. Aapki app sirf purane phones par `NoSuchMethodError` deti hai. Teen SDK settings mein se
   kaun si galat hai, aur fix kya hai?
3. Sandbox ke aadhar par samjhao ki ek to-do app banking app ka saved session kyun nahi
   padh sakti — bina "security" shabd use kiye.
4. Aapka APK 40 MB ka hai. Do wajah batao ki AAB se asli download chhota kyun ho jayega.

## Recap

| Term | Ek line |
| --- | --- |
| Linux kernel | Sabse neeche ki layer; user-ID sandbox ka srot |
| HAL | Alag-alag manufacturers ke hardware tak sthir interface |
| ART | Android ka runtime — DEX chalata hai, pehle hi compile karta hai |
| DEX | Android ka bytecode format, R8 banata hai |
| Sandbox | Har app ka ek Linux user; permission uske bahar ki anumati hai |
| API level | Wo number jise build target karti hai, jaise Android 15 ke liye 35 |
| AAB | Jo aap upload karte ho; Play isse per-device APK banata hai |

<Interview title="Ye dekhne ke liye poochha jata hai ki platform samajh aaya ya sirf SDK">
"`minSdk`, `targetSdk` aur `compileSdk` mein kya farak hai?"

Jo jawab jamta hai: `compileSdk` compile time hai, `minSdk` install time hai, `targetSdk`
run time hai. Phir har ek ke galat hone ka nateeja batao — code compile hi nahi hoga, users
install nahi kar payenge, aur wo behaviour badal jayega jo aapne kabhi test hi nahi kiya.
</Interview>
