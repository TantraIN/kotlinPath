Android ek thread — **main thread** — sirf drawing aur input ke liye rakhta hai. 60fps ke liye
har frame lagbhag 16ms mein banna chahiye.

Us thread par koi bhi dheemi cheez matlab jama hua app.

## Pehla ilaaj: doosra thread

```kotlin title="Threads.kt" numbered
fun loadUser() {
    Thread {
        val user = api.fetchUser()          // dheema, par ab main par nahi
        runOnUiThread { showUser(user) }    // draw karne ke liye wapas aana padta hai
    }.start()
}
```

Ye chalta hai, aur isiliye 2019 se pehle har Android app aisi hi dikhti thi. Isme teen asli
dikkatein hain.

| Dikkat | Kyun maayne rakhti hai |
| --- | --- |
| Threads mehnge hain | Har ek ka lagbhag 1MB stack; hazaron nahi rakh sakte |
| Cancel karne ka tarika nahi | User screen chhod deta hai; thread chalta rehta hai |
| Result wapas laana padta hai | Main ke bahar View chhuo to exception aata hai |

## Doosra ilaaj: callbacks, aur wo bigadte kahan hain

```kotlin title="Callbacks.kt" numbered
fun loadScreen() {
    api.fetchUser { user ->
        api.fetchOrders(user.id) { orders ->
            api.fetchAddress(user.id) { address ->
                showScreen(user, orders, address)
                // aur ab teeno mein error handling bhi jodo
            }
        }
    }
}
```

Har kadam theek hai. Ek ke andar ek rakhne par aisa code banta hai jahan chalne ka order aur
likhe hue ka order ek nahi rehte.

<Pitfall bare>
Upar wale mein error handling jodo aur har level ko apni alag failure branch chahiye. Aisa koi
`try` hai hi nahi jo teeno ko lapet le, kyunki teeno ek hi stack par hain hi nahi.
</Pitfall>

<Detail summary="Bas aur threads kyun na bana lein">
Ek thread lagbhag ek megabyte stack leta hai aur use schedule karne mein kernel-level context
switch lagta hai. Das hazaar threads mumkin hi nahi. Das hazaar coroutines aam baat hai, kyunki
suspended coroutine bas heap par pada ek object hai — intezaar ke dauraan wo koi thread pakadta
hi nahi.
</Detail>

## Practice

1. Likho ki main thread par 3 second ki image upload ke dauraan aapka app kar kya raha hai. Un
   secondon mein kya kiya ja sakta tha?
2. Upar wale nested callback example mein har level par error handling jodo. Branches gino.
3. Apne project ke liye 60fps aur 120fps ka frame budget milliseconds mein dekho.
4. Jo app aap use karte ho usme ek aisa kaam batao jo saaf taur par background thread par chalta
   hai. Bahar se ye kaise pata chalta hai?

## Recap

| Term | Matlab |
| --- | --- |
| Main thread | Akela thread jise draw aur input ki ijazat hai |
| Blocking | Intezaar ke dauraan thread pakadna — yahi keemat hataani hai |
| Frame budget | 60fps par ~16ms, 120fps par ~8ms |
| ANR | Android ka "Application Not Responding" dialog |
| Callback hell | Nested callbacks jahan chalne ka order padhne ke order se alag ho jata hai |
