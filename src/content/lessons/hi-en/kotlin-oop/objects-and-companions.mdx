<KeyIdea>
`object` koi aisi class nahi batata jise aap bana sako. Wo khud hi **wo instance hai** — ek baar,
pehle istemal par bana hua.
</KeyIdea>

```kotlin title="Singleton.kt" numbered runnable
object AppConfig {
    val baseUrl = "https://api.example.com"
    var retries = 3
}

fun main() {
    AppConfig.retries = 5
    println(AppConfig.retries)          // 5, har jagah
    println(AppConfig === AppConfig)    // true — ek hi to hai
}
```

## Teen roop

<Tabs>
  <Tab label="object declaration">

Naam wala singleton. Config, registry, ya bina state wala helper.

```kotlin title="Declaration.kt" numbered
object Analytics {
    fun track(event: String) = println("track $event")
}

// Analytics.track("open")
```

  </Tab>
  <Tab label="companion object">

Class se juda hua, isliye class ke private members tak pahunch sakta hai. Factories yahin rehti hain.

```kotlin title="Companion.kt" numbered runnable
class User private constructor(val name: String) {

    companion object {
        fun of(raw: String): User? =
            raw.trim().takeIf { it.isNotEmpty() }?.let(::User)
    }
}

fun main() {
    println(User.of("  Asha ")?.name)
    println(User.of("   ")?.name)      // null — mana kar diya
}
```

Private constructor aur companion factory ka matlab hai ki galat object banaya hi nahi ja sakta.

  </Tab>
  <Tab label="object expression">

Ek baar ka bina-naam wala object — Kotlin ka anonymous inner class wala jawab.

```kotlin title="Expression.kt" numbered
val comparator = object : Comparator<String> {
    override fun compare(a: String, b: String) = a.length - b.length
}
```

Baaki do ke ulat, ye expression jitni baar chalega utne naye bante hain.

  </Tab>
</Tabs>

<Detail summary="`static` hai hi nahi, aur ye jaan-boojh kar hai">
`static` member kisi instance ka hota hi nahi, isliye wo na interface implement kar sakta hai na
override ho sakta hai. Companion object ek asli object hai, isliye dono kar sakta hai — companion
`Factory<T>` implement karke idhar-udhar bheja ja sakta hai. Kotlin ne ek keyword chhoda aur
badle mein ek value paayi.
</Detail>

## Common galtiyan

<Pitfall title="Do jo khaas taur par Android par kaatti hain">
**`object` mein `Context` rakhna.** Singleton har Activity se zyada jeeta hai, isliye jis
Activity ko wo pakde hai wo kabhi collect nahi ho sakti. Ye kitabi memory leak hai.
`applicationContext` rakho, ya usse behtar, jo chahiye wahi paas karo.

**Singleton mein badalne wali state.** `object Cache { var user: User? = null }` har thread aur
har screen se pahunch mein hai, na koi maalik na koi lifecycle. Ye achhe kapdon mein global
variable hai. Ek scoped instance banao aur use paas karo.
</Pitfall>

## Practice

1. `AppConfig` mein ek `var count` jodo, do alag functions se badhao, aur print karo. Dekho ki
   dono ko wahi number dikhta hai.
2. Private constructor wali `Temperature` class likho, aur companion factories `fromCelsius`
   aur `fromFahrenheit` banao.
3. `object` ki body mein `println` daalo aur use do baar chhuo. Confirm karo ki theek ek baar
   chhapta hai.
4. Badalne wali state wale `object` ko ek class se badlo jise aap banate ho aur paas karte ho.
   Kis version ko test karna aasan hai?

## Recap

| Form | Kitne instances | Kis liye |
| --- | --- | --- |
| `object Name { }` | Theek ek, pehle istemal par | Config, registry, bina state ka helper |
| `companion object` | Har class ka ek | Factories, constants, private tak pahunch |
| `object : Type { }` | Har baar naya | Ek baar ka listener ya comparator |
| Kotlin ka `static` | Hai hi nahi | Companion uthao, ya top-level function |
