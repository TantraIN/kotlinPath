<KeyIdea>
Bane-banaye project mein kuchh bhi bharti nahi hai. Har file us sawaal ka jawaab
hai jo build ka tantra, operating system ya Play Store aapse aage poochhega — aur
Android se darna chhodne ka sabse tez raasta yeh jaanna hai ki kaun si file kis
sawaal ka jawaab deti hai.
</KeyIdea>

## Hum bana kya rahe hain

**Saathi** ek shared list hai. Aap apne phone par bread aur doodh jodte hain; jise
aapne APK bheja tha use donon apne phone par dikhne lagte hain. Yeh bina signal
wali dukaan mein chalta hai, aur signal lautne par sync kar leta hai.

Wahi ek vaakya zyadatar banaavat tay kar deta hai, aur hum baar-baar usi par
lautenge. Bina net chalne ka matlab hai sach ka srot net nahi, database hai. Shared
hone ka matlab hai koi user hai, aur niyam hain ki kaun kya padh sakta hai.

## Ise banana

Android Studio mein: **New Project → Empty Activity**. Chaar khaane, aur har ek
aisa faisla hai jise saste mein palta nahi ja sakta.

| Khaana | Kya rakhiye | Aage kyon maayne rakhta hai |
| --- | --- | --- |
| Name | `Saathi` | Icon ke neeche likha naam. Kabhi bhi badla ja sakta hai. |
| Package name | `com.sujeet.saathi` | Yahi `applicationId` banta hai — app ki pakki pehchaan |
| Save location | kahin bhi, bina space wale raaste par | Kuchh native auzaar aaj bhi raaste ke space par ladkhadate hain |
| Minimum SDK | `API 24` | Sabse purana Android jis par chalne ka aap waada karte hain |

**Package name** chalan ke mutaabik ulte domain jaisa hota hai kyonki use duniya
bhar mein alag hona hai — ek hi naam wale do app na kisi upkaran par saath reh sakte
hain na Play par. Koi aisa domain lijiye jo aapka ho, ya aisa naam jo koi aur na
chune.

**Minimum SDK** asli sauda hai. Android Studio har star ke liye dikhata hai ki wo
kitne upkaranon tak pahunchta hai, aur aap jitna neeche jaate hain utni APIs khote
hain. API 24 aaraamdeh farsh hai: chalan mein lagbhag har phone usmein aata hai aur
phir bhi aap zyadatar aaj ke Jetpack ko bina alag-alag shaakhaon ke istemaal kar
sakte hain.

Inmein se teen abhi kholne layak hain.

### `settings.gradle.kts` — cheezein aati kahan se hain

```kotlin title="settings.gradle.kts" numbered
pluginManagement {
    repositories {
        google()          // Android Gradle Plugin, Jetpack
        mavenCentral()    // baaki sab kuchh
    }
}
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories { google(); mavenCentral() }
}
include(":app")
```

Yeh file usi sawaal ka jawaab hai — *yeh aata kahan se hai*. Jab aap koi dependency
likhte hain, Gradle yahan likhe har repository se tarteeb se poochhta hai, aur pehla
milta hua `~/.gradle/caches` mein utaar leta hai. Kuchh bhi Android Studio ke saath
nahi aata.

`include(":app")` aapke project ke modules ki poori soochi hai. Jo module aap
banakar yahan likhna bhool jaayein wo Gradle ke liye hai hi nahi, aur jo error milti
hai wo is file ke baare mein kuchh nahi kehti.

### `gradle/libs.versions.toml` — version ka catalog

```toml title="gradle/libs.versions.toml" numbered
[versions]
kotlin = "2.1.0"
composeBom = "2025.01.00"

[libraries]
androidx-core-ktx = { group = "androidx.core", name = "core-ktx", version.ref = "coreKtx" }
compose-bom = { group = "androidx.compose", name = "compose-bom", version.ref = "composeBom" }

[plugins]
android-application = { id = "com.android.application", version.ref = "agp" }
```

yahi file hai, aur binduon wala raasta wahi naam hai jismein hyphen binduon mein
badal gaye. To code ki ek line ka poora safar yeh hai:

### `app/build.gradle.kts` — yahi module

```kotlin title="app/build.gradle.kts" numbered
android {
    namespace = "com.sujeet.saathi"        // R aur BuildConfig kahan bante hain
    compileSdk = 36                         // kaun si APIs aap bula sakte hain

    defaultConfig {
        applicationId = "com.sujeet.saathi" // pakki pehchaan
        minSdk = 24                         // sabse purana upkaran jise aap sahara dete hain
        targetSdk = 36                      // wo bartaav jis par aapne parakh ki hai
        versionCode = 1                     // Play yahi milata hai; badhna hi chahiye
        versionName = "1.0"                 // user ko dikhne wala
    }
}
```

`compileSdk`, `minSdk` aur `targetSdk` teen alag sawaal hain aur lagataar aapas mein
gaddmadd kiye jaate hain. `compileSdk` yeh hai ki compiler aapko kaun si APIs likhne
deta hai. `minSdk` sabse purana upkaran hai jis par app lag sakta hai. `targetSdk`
ek waada hai: *maine is version ke bartaav ke badlaavon par parakh kar li hai* — aur
use badhana aapko peechhe chalte kaam ki sakht hadon jaisi cheezon mein shaamil kar
deta hai, chahe aap taiyar hon ya nahi.

<Detail summary="`namespace` aur `applicationId` alag kyon hain">
Wo shuru mein ek jaise hote hain, to dohraav lagte hain. Hain nahi.

`namespace` compile waqt ki cheez hai: wo tay karta hai ki bani hui `R` aur
`BuildConfig` classes kis package mein jaayengi, to aapki Kotlin ki `import` lainein
usi ki baat karti hain. `applicationId` chalte waqt ki cheez hai: wahi pehchaan hai
jisse operating system aur Play lage hue app ko pehchante hain.

Wo alag isliye hain ki build ke roopon ko ek badalna padta hai aur doosra nahi.
Release wale step mein hum debug wale build ko `applicationIdSuffix = ".debug"`
denge taki wo parakhne wale ke phone par release wale ke *saath-saath* lage — Android
ke liye do app, compiler ke liye ek namespace, aur kahin koi code ka badlaav nahi.
</Detail>

## Wo ek screen jo aapko mili

```kotlin title="MainActivity.kt" numbered
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            SaathiTheme {
                Scaffold { padding -> Greeting(Modifier.padding(padding)) }
            }
        }
    }
}
```

`ComponentActivity` chhota, Compose se mel khaata aadhaar class hai — wo lifecycle,
`ViewModel` ka bhandaar aur back dabane wala dispatcher laata hai jin par hum aage ke
step mein tikenge, aur kuchh nahi. `setContent` wo pul hai: us line se neeche aap
Compose mein hain aur kahin koi XML ka layout nahi hai.

`enableEdgeToEdge()` aapke app ko status aur navigation ki pattiyon ke peechhe tak
banata hai, jo Android 15 aur usse aage zaroori hai. Isiliye `Scaffold` aapko
`padding` ka maan thamata hai — use chhodiye aur aapki saamagri ki pehli pankti ghadi
ke neeche baith jaayegi.

## Ek baar chalaiye

Run dabaiye. Teen cheezein hoti hain jinhein dimaag mein alag rakhna kaam ka hai:
Gradle dependencies suljhakar compile karta hai, APK par us **debug ki chaabi** se
hastakshar hote hain jo Android Studio ne aapke liye banai, aur `adb` use laga deta
hai.

Wahi debug ki chaabi hai jiski wajah se app lagta hi hai — Android bina hastakshar
wale APK thukra deta hai — aur usi wajah se aap yeh build kisi dost ko bhejkar baad
mein release wale build se update nahi kar sakte. Alag chaabi, alag app. Ise hum
aakhri step mein theek se suljhaayenge.

<Pitfall title="Teen cheezein jo pehle hi din kaat-ti hain">
**`libs.versions.toml` badalkar sync na karna.** Catalog sync ke waqt padha jaata
hai, to nayi entry sync tak dikhti hi nahi — aur error kehti hai "unresolved
reference", jo code ki gadbadi jaisi lagti hai.

**Build baant dene ke baad `applicationId` badalna.** Wo hamesha naya app hai. Kisi
ke kuchh lagane se pehle use chun lijiye.

**`local.properties` commit kar dena.** Usmein *aapke* SDK ka poora raasta hai. Bani
hui `.gitignore` use pehle hi chhod deti hai; use "theek" mat kijiye.
</Pitfall>

## Parakh ka padaav

Agle step se pehle, yeh sab sahi hona chahiye.

| Parakh | Kaise pata chalega |
| --- | --- |
| Project banta hai | Run poora hota hai, app upkaran par khulta hai |
| Jad ki har file ka naam bata sakte hain | `settings`, `build`, `libs.versions.toml`, wrapper |
| Dependency kahan se aati hai, pata hai | Catalog se pata, pate se repository, phir bhandaar |
| `applicationId` aakhri hai | Aap use hamesha ke liye rakhne ko taiyar hain |
| Git shuru ho chuka hai | `git init`, aur bani hui `.gitignore` bina chhede |

Aage: is project ko Firebase se jodiye, aur theek-theek dekhiye ki
`google-services.json` karta kya hai — yeh bhi ki use commit karna surakshit kyon
hai, jo lagbhag sabko chaunkata hai.
