<KeyIdea>
Route ek **pata hai, maal nahi**. Jis cheez ki baat hai uski pehchaan bhejiye; use laane
ka kaam manzil par chhodiye. Poori cheez liye chalta route suvidhajanak dikhta hai aur
pehli hi baar toot jaata hai jab screen khuli rehte data badal jaaye — ya process disk
se lautaya jaaye.
</KeyIdea>

## Kism se surakshit routes

```kotlin title="ui/Routes.kt" numbered
@Serializable data object ListsRoute
@Serializable data class ListRoute(val listId: String)
@Serializable data class EditItemRoute(val listId: String, val itemId: String)
```

Teen ghoshnaayein aur ek plugin — `kotlinx-serialization` — un string wale routes ki
jagah le lete hain jo Navigation ko pehle chahiye the. Yeh farak sajaavati nahi hai:
strings ke saath `"list/{listId}"` aur argument ke naam mein ek akshar ki galti aaraam se
compile hoti hai aur chalte waqt null argument se girti hai. Inke saath chhoota ya galat
naam wala argument compile ki error hai.

```kotlin title="ui/SaathiNavHost.kt" numbered
NavHost(navController = navController, startDestination = ListsRoute) {

    composable<ListsRoute> {
        ListsScreen(onOpen = { listId -> navController.navigate(ListRoute(listId)) })
    }

    composable<ListRoute> {
        ListScreen(
            onEdit = { itemId -> navController.navigate(EditItemRoute(listId, itemId)) },
            onBack = { navController.navigateUp() },
        )
    }

    composable<EditItemRoute> {
        EditItemScreen(onDone = { navController.popBackStack() })
    }
}
```

`navigate(ListRoute(listId))` koi saji hui string nahi, ek asli cheez leta hai. Wo route
wali cheez back ke dher ki entry mein saheji jaati hai, aur ViewModel mein
`savedStateHandle.toRoute<ListRoute>()` use wapas padh leta hai — wahi line jo aap
pichhle step mein likh chuke hain.

## Back ke dher ko sambhalna

Navigate karna aasaan hai; yeh tay karna ki user kis par laut sakta hai, wahi hissa hai
jiske niyam hain.

```kotlin title="Login wali screen hataana" numbered
navController.navigate(ListsRoute) {
    popUpTo<LoginRoute> { inclusive = true }   // login hataiye, khud use bhi
    launchSingleTop = true                     // doosri nakal mat chadhaiye
}
```

Bina `popUpTo` ke, sign in karne ke baad back dabana user ko usi app ki login wali screen
par lauta deta hai jismein wo pehle hi signed in hai. Auth wale app mein yeh sabse aam
navigation ki gadbadi hai, aur ek vikalp use theek kar deta hai.

`launchSingleTop` wahan maayne rakhta hai jahan koi manzil apne hi aap tak pahunch sakti
ho — koi notification wahi list khole jo user pehle se dekh raha hai, ya kisi pankti par
do baar chhoona. Uske bina ek screen chhodne ke liye back do baar dabana padta hai.

| Vikalp | Kab lijiye |
| --- | --- |
| `popUpTo(route)` | Peechhe ki screens par lautna nahi chahiye |
| `inclusive = true` | Khud wo manzil bhi hat jaani chahiye — login, onboarding |
| `launchSingleTop` | Manzil apne hi aap se dobara khul sakti hai |
| `restoreState` | Neeche wale tabs jinhein apni scroll ki jagah yaad rakhni hai |

<Detail summary="`navigateUp` aur `popBackStack` ek hi call nahi hain">
Zyadatar waqt wo ek jaisa bartaav karte hain, aur isiliye farak sirf usi maamle mein
dikhta hai jo maayne rakhta hai.

`popBackStack()` *aapke* back ke dher ki oopar wali entry hataata hai. Agar wo khaali
hai, kuchh nahi hota aur user phans jaata hai.

`navigateUp()` mezbaan se poochhta hai — jo koi doosra app bhi ho sakta hai. Jab aapki
screen kisi deep link se khuli ho, ya kisi aur app ki share wali chaadar se, to
`navigateUp` user ko wahin lauta deta hai. Toolbar ke teer se insaan yahi ummeed karta
hai, aur isiliye toolbar ka Up `navigateUp()` bulaye aur screen ke bheetar ka "Done" wala
button `popBackStack()`.

Yeh share wale step mein thos ho jaayega, jab WhatsApp se aaya koi link app ko seedhe kisi
list par kholta hai aur peechhe koi dher hota hi nahi.
</Detail>

## ViewModel rehta kahan hai

```kotlin title="Manzil ke daayre mein" numbered
composable<ListRoute> {
    val viewModel: ListViewModel = hiltViewModel()   // isi back stack ki entry ke daayre mein
    ListScreen(viewModel)
}
```

`composable` wale hisse ke bheetar `hiltViewModel()` us ViewModel ko usi navigation ki
entry ke daayre mein rakhta hai, Activity ke nahi. To dher par padi do alag lists ko do
ViewModel milte hain, do `listId` ke saath, aur koi screen hataane par uska ViewModel bhi
mit jaata hai.

Lagbhag hamesha aap yahi chaahte hain. Apvaad wo haalat hai jo sach mein screens mein
saajha ho — koi kai-kadamon wala form — jahan aap use oopar wale graph ki entry ke daayre
mein rakhte hain, aur Activity ke daayre wala ViewModel uthane ke bajay saaf-saaf kehte
hain.

<Pitfall title="Chaar, aur pehli do kisi bhi parakhne wale ko ek minute mein dikh jaati hain">
**Route ke arguments mein poori cheezein bhejna.** Thodi der baad baasi data, aur process
ke marne ke baad bhi.

**Sign in ke baad `popUpTo` na lagana.** Back signed in app ki login wali screen par lauta
deta hai.

**`launchSingleTop` chhootna.** Ek hi screen ki nakal chadh jaati hai aur back do baar
dabana padta hai.

**Toolbar ke teer par `popBackStack()`.** Deep link se khuli screen ke paas hataane ko
kuchh nahi hota, aur Up kuchh karta hi nahi.
</Pitfall>

## Parakh ka padaav

| Parakh | Kaise pata chalega |
| --- | --- |
| Routes kism se surakshit hain | Arguments strings nahi, constructor ke parameters hain |
| Sirf pehchaanein safar karti hain | Koi route domain ki cheez liye nahi chalta |
| Login dher mein nahi hai | Sign in ke baad back app se bahar le jaata hai, login par nahi |
| Har manzil ka apna ViewModel | Dher par padi do lists apni-apni haalat rakhti hain |
| Up aur back alag hain | Toolbar ka teer `navigateUp()` bulata hai |

Aage: user ke back dabane par asal mein hota kya hai — aur wo ishaare wali jhalak jo
seedhe dikhne wale tareeke se sambhalne par toot jaati hai.
