Ise neeche se padhiye aur dekhiye ki kya gaayab hai: Firestore se ViewModel tak koi
kadam hai hi nahi. Screen tak ka har raasta database se hokar jaata hai.

## DAO koi Flow lautata hai

```kotlin title="data/local/ItemDao.kt" numbered
@Dao
interface ItemDao {
    @Query("SELECT * FROM items WHERE listId = :listId ORDER BY done, updatedAt DESC")
    fun observeItems(listId: String): Flow<List<ItemEntity>>   // suspend nahi — yeh dobara bolta hai

    @Upsert
    suspend fun upsert(items: List<ItemEntity>)

    @Query("SELECT * FROM items WHERE pendingSync = 1")
    suspend fun pending(): List<ItemEntity>

    @Query("DELETE FROM items WHERE listId = :listId AND id NOT IN (:keep)")
    suspend fun deleteMissing(listId: String, keep: List<String>)
}
```

Pehla function hi zaroori hai, aur dhyaan dene ki baat yeh hai ki wo `suspend`
**nahi** hai. Rukne wali query ek baar jawaab deti hai. `Flow` wali query Room ke
badlaav par nazar rakhne wale se jud jaati hai aur har baar jab `items` ki table mein
kuchh likha jaaye tab dobara bolti hai — us likhne samet jo Firestore se aaya ho, kisi
bilkul alag coroutine mein, kuchh second baad.

Poori chalaaki yahi hai. Screen net ki sadasyata nahi leti; wo table ki sadasyata leti
hai, aur net bas usi mein likh deta hai.

`@Upsert` isi wajah se maayne rakhta hai. Sync aise documents laata hai jo yahan pehle
se ho bhi sakte hain aur nahi bhi, aur ek hi vaakya mein daalo-ya-badlo, sync likhne
wale aur usi pal chhoote user ke beech padho-phir-tay-karo wali daud se bacha leta hai.

## Likhna

```kotlin title="data/ItemRepository.kt" numbered
class ItemRepository @Inject constructor(
    private val dao: ItemDao,
    private val workManager: WorkManager,
) {
    fun items(listId: String): Flow<List<Item>> =
        dao.observeItems(listId).map { entities -> entities.map(ItemEntity::toDomain) }

    suspend fun add(listId: String, text: String, uid: String) {
        dao.upsert(listOf(
            ItemEntity(
                id = UUID.randomUUID().toString(),
                listId = listId,
                text = text,
                done = false,
                addedBy = uid,
                updatedAt = System.currentTimeMillis(),
                pendingSync = true,                    // server ko abhi khabar nahi
            ),
        ))
        SyncWorker.enqueue(workManager)                // kahiye; intezaar mat kijiye
    }
}
```

`add` Room mein likhkar laut aata hai. Wo net ko chhoota nahi, koi `Result` lautata
nahi, aur bulane wale ke paas intezaar karne ko kuchh hai hi nahi — kyonki wo cheez
database mein pahunch chuki hai, to `Flow` dobara bol chuka hai aur screen badal chuki
hai.

Firestore ko seedhe bulane ke bajay worker kataar mein daalna hi ise us haal mein
bachata hai jab user ek second baad app band kar de.

## Ise saabit kijiye

Yahi wo step hai jahan aap daava sach mein parakh sakte hain, to parakhiye.

1. App chalaiye aur teen cheezein jodiye.
2. Aeroplane mode chaalu kijiye.
3. Haal wali soochi se app maariye aur dobara kholiye.

Soochi screen par tab honi chahiye jab tak aap use aate dekh bhi na paayein — database
ki padhai, koi maang nahi. Bina net rehte hue chauthi cheez jodiye; wo turant dikhti
hai, abhi na bheji hui ke nishaan ke saath. Wo chauthi cheez Room mein
`pendingSync = true` ke saath padi hai aur net ki shart ke peechhe `WorkManager` ki ek
maang kataar mein hai.

<Detail summary="Do cheezein jo database mein asli data aate hi kaatengi">
**Migrations.** App bhejte hi `fallbackToDestructiveMigration()` ka matlab hai ki
update user ka bina net wala data mita dega. Asli `Migration` likhiye, aur schema
bahar bhejiye taki Room uska farak bata sake:

```kotlin title="Schema bahar bhejna" numbered
ksp { arg("room.schemaLocation", "$projectDir/schemas") }
```

`schemas/` wali directory commit kijiye. Uske bina Room aapko yeh bata hi nahi sakta ki
kya badla, aur aap migrations yaaddaasht se likh rahe honge.

**Kaun sa dhaaga.** DAO ka `suspend` wala function kisi bhi coroutine se bulana
surakshit hai; Room use mukhya dhaage se khud hata leta hai. `Flow` wali query bhi
surakshit hai. Asurakshit wo DAO ka function hai jo na suspend hai na Flow — Room use
wahin chalayega jahan aapne bulaya, aur mukhya dhaage par wo tayshuda taur par girta
hai, jo framework ka aap par ehsaan hai.
</Detail>

<Pitfall title="Chaar, aur pehli wo hai jo chupchaap poora step palat deti hai">
**ViewModel mein net se collect karna.** Bina net hona phir khaas maamla ban jaata hai,
aur har screen apni loading wali haalat uga leti hai.

**Soochi ke liye `suspend` wali DAO query.** Wo ek baar jawaab deti hai, to sync ka
likha screen tak kabhi nahi pahunchta aur soochi tab tak baasi dikhti hai jab tak aap
jaakar laut na aayein.

**`add` ke bheetar net ka intezaar.** Train mein button ghoomta rehta hai. Yahin
likhiye, kataar mein daaliye, laut aaiye.

**Bheje hue build mein `fallbackToDestructiveMigration()`.** Update chupchaap wo sab
mita deta hai jo user ne bina net joda tha.
</Pitfall>

## Parakh ka padaav

| Parakh | Kaise pata chalega |
| --- | --- |
| UI sirf Room padhti hai | Koi ViewModel Firestore import nahi karta |
| Query ek `Flow` hai | Sync ke likhte hi bina refresh dobara bolti hai |
| Jodna turant hai | Net band rehte cheez dikhti hai |
| Bakaya dikhta hai | Bina bheji cheez UI mein nishaan wali hai |
| Migrations asli hain | `schemas/` commit hai, koi mitaane wala fallback nahi |

Aage: deewar ki doosri taraf — Firestore, wo suraksha niyam jo aapka akela server hain,
aur wo chakkar jo badlaav donon taraf le jaata hai.
